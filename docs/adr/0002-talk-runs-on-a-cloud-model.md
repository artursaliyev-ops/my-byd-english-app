# Talk runs on a cloud model over the phone's hotspot

Talk sends each Turn to a cloud model through the phone's hotspot, so it does not work without a network. We tried an on-device model first: on the owner's car (Qualcomm QCM6490, 2026-11-21), BYD's dashcam and cameras keep about 3 of the 8 cores busy. That held Qwen3.5-2B on llama.cpp to ~4.5 tok/s, or about 5 s from the end of speech to the first answer audio, against a 3–5 s bar. It also passed only ~2 of 10 talk partner test cases. Qwen3.5-0.8B was fast enough but passed ~3/10. Prompt tuning can't close a gap that comes from model size, and nothing in the app can lower BYD's load. We also rejected keeping the small offline model as a no-network fallback: it would mean a second stack that still talks badly. Revisit this only if the head unit gains a usable NPU path or BYD's background load drops. Measurements: [Measure a Turn on the car with the offline stack](../../.scratch/voice-talk/issues/03-measure-a-turn.md).
